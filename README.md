# Trust Before Throughput — FAP-Selective Radioligand Warheads (AIDD8122 Final Project)

**Author:** Huang Yong (P2600222) · AIDD8122, Macao Polytechnic University · November 2026

**This repository holds source code only.** It contains the numbered analysis
pipeline and the delivery scripts that produced the report and the deck. Curated
data, result tables, figures, the report and the slides are **not committed**:
they are regenerated by the scripts (into `data/` and `results/` on your machine)
or supplied in the submission package, where these scripts sit in `03_Code/`
next to `04_Results/` and `05_Data/`.

The project asks what machine learning can actually deliver for FAP-targeted
radiopharmaceutical design given the public ChEMBL record — and where the answer
is negative.

Delivery utilities (`14`–`35`, `pack_submission.py`) are formatting passes, not
analysis steps. `18`–`19` were one-off re-layouts of a working draft.

## Reproduction

```bash
pip install -r requirements.txt
python src/01_fetch_chembl.py     # needs internet access to www.ebi.ac.uk
python src/02_curate.py
python src/03_benchmark.py --target FAP --seeds 5
python src/04_transfer.py --seeds 20
python src/05_analysis.py
python src/06_generative.py --generations 24 --pop 96   # ~30 min on CPU
python src/07_figures.py && python src/08_workflow.py
python src/09_build_report.py
python src/11_reference_dois.py && python src/12_design_feasibility.py && python src/13_robustness.py
```

The scripts create `data/raw/`, `data/processed/`, `results/tables/`,
`results/figures/` and `report/` on first run; none of those paths is tracked, so
a fresh clone regenerates them from the public API.

**Package view.** When this README is copied into
`Submission_HuangYong_P2600222/03_Code/`, the generated paths sit alongside the
code: `results/tables/` → `../04_Results/tables/`, `results/figures/` →
`../04_Results/figures/`, `data/processed/` → `../05_Data/`, `report/` →
`../01_Report/`. Appendix A of the report quotes the package paths directly.
